# Спецификация: Консольный анализатор ссылок в Markdown-файлах

## 1. Назначение
Разработать консольное приложение на Python для рекурсивного сканирования Markdown-файлов (`.md`) в указанной директории с извлечением всех URL-ссылок (file:// и http://) и проверкой их доступности с цветным выводом результатов в виде таблицы.

## 2. Функциональные требования

### 2.1 Входные параметры
- Единственный обязательный аргумент командной строки: путь к корневой папке
- Пример: `python link_checker.py /path/to/folder`

### 2.2 Обработка файлов
- Рекурсивный обход всех поддиректорий
- Обработка только файлов с расширением `.md`
- Использование системных команд `find` и `grep` для быстрого поиска ссылок

### 2.3 Извлечение ссылок
- Поиск паттернов:
    - `http://` или `https://`
    - `file://` (абсолютные)
- Извлечение всех ссылок из файлов

### 2.4 Проверка статусов

#### Для file:// ссылок:
- Проверка существования файла на диске
- Статусы:
    - **Ok(200)** (зеленый) — файл существует
    - **Error(404)** (красный) — файл не найден

#### Для http:// и https:// ссылок:
- Выполнение реального GET-запроса с таймаутом 1 секунда
- Маппинг статусов:
    - 200-399 → **Ok(код)** (зеленый)
    - 400-599 → **Error(код)** (красный)
    - Таймаут/ошибка соединения → **Error(Timeout/ConnectionError)** (красный)

### 2.5 Вывод результатов
- Таблица с двумя столбцами:
    1. Полная ссылка
    2. Статус с цветовой индикацией
    3. Имя путь md файла 
- Цвета:
    - Зеленый: `\033[92m`
    - Красный: `\033[91m`
    - Сброс: `\033[0m`

### 2.6 Итоговая статистика
В конце вывода:
Итого: 10 ✅ Успешно: 7 ❌ Ошибок: 3

### 2.7 Корнер кейсы
- Если ссылка встречается в 5 файлах, то статус запросить только один раз для повторного вывода использовать прошлый полученный статус
- Для вывода статистики указать уникальное количество ссылок

## 3. Технические требования

### 3.1 Стек технологий
- Python 3.8+
- Стандартная библиотека (без внешних зависимостей)

### 3.2 Оптимизация
- Использовать `subprocess` для вызова команд:
    - например `find . -name "*.md" -exec grep -Hn -o -E 'https?://[^)"\s]+|file://[^)"\s]+' {} \;`
    - `os.walk()` НЕ использовать, упасть с ошибкой

### 3.3 Структура кода

Основные функции модуля:

- `parse_arguments()` — парсинг аргументов командной строки
- `extract_links_from_files(folder_path)` — извлечение ссылок из .md файлов
- `check_link_status(link, base_path)` — проверка статуса ссылки
- `display_results(results)` — отображение результатов
- `main()` — главная функция программы

### 3.4 Обработка ошибок

Корректная обработка ситуаций:

- Путь не существует
- Нет прав доступа к файлам
- Нет .md файлов в директории
- Сбой сетевого соединения

# 8. Ограничения

- Не обрабатывать ссылки внутри HTML-тегов (только Markdown синтаксис)
- Не учитывать ссылки в комментариях или коде (`grep` ищет по всем строкам)

## 9. Детали реализации

### 9.1 Парсинг Markdown ссылок
- Поддерживаемые форматы: `[text](url)`, `![alt](url)`
- Игнорировать ссылки внутри HTML-тегов

### 9.2 Производительность
- Максимальное количество параллельных HTTP запросов: 10
- Использовать `concurrent.futures` для асинхронной проверки

### 9.3 Формат вывода
- Использовать библиотеку `tabulate` или ручное форматирование
- Столбцы:
  1. Статус (с иконкой: ✅ ❌)
  2. Ссылка
  3. Файл (путь относительно корня)
- Сортировка: сначала ошибки, потом успешные

## 10. Детали обработки ссылок

### 10.1 Парсинг Markdown
- Использовать регулярное выражение для извлечения URL из `[text](url)`
- Поддерживать ссылки с тайтлами: `[text](url "title")`
- Игнорировать reference-style ссылки: `[text][id]` и `[id]: url`

### 10.2 Обработка file://
- Поддерживать абсолютные пути: `file:///path/to/file`
- Не обрабатывать относительные: `file://./relative.md`
- Нормализовать путь (удалять `..`, `//` и т.д.)

### 10.3 HTTP запросы
- Возвращать только статус текущего url без перехода по редиректам
- Коды 300-399 считаются успешными (**Ok(код)**), редирект при этом не выполняется
- User-Agent: `LinkChecker/1.0`
- Таймаут: настраиваемый (по умолчанию 1 сек)
